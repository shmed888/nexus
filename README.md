# Nexus — Dark Premium Messenger MVP

Nexus — небольшой самохостящийся браузерный мессенджер: тёмный адаптивный UI на HTML/CSS/JavaScript, Node.js + Express API, PostgreSQL/Prisma и Socket.IO. Проект не использует социальную ленту, публикации, лайки или комментарии.

> **Статус сборки:** исходники и первоначальная Prisma migration созданы. В этой среде сетевой доступ к npm registry недоступен, поэтому зависимости не были установлены, полноценный `package-lock.json` не был создан, Prisma Client не был сгенерирован и интеграционный запуск с PostgreSQL не выполнялся. Не воспринимайте этот архив как доказанно запущенную или production-готовую систему. После установки зависимостей выполните проверки из раздела «Проверка».

## Требования

- Node.js 22.18+ (можно использовать совместимый актуальный Node.js; в среде автора доступен Node 22, пользовательский компьютер может отличаться).
- npm.
- PostgreSQL 14+; либо Docker Compose для отдельного сервиса PostgreSQL.
- Для реальных WebRTC-звонков вне localhost — HTTPS и, в некоторых сетях, собственный TURN-сервер.

## Запуск на Arch Linux / Fish

### Вариант A — локальный PostgreSQL

1. Установите Node.js/npm и PostgreSQL из репозиториев Arch, если их ещё нет.
2. Инициализируйте PostgreSQL (если он ещё не был инициализирован) и запустите службу. Не повторяйте `initdb`, если в `/var/lib/postgres/data` уже есть рабочая база.

```fish
sudo -iu postgres initdb -D /var/lib/postgres/data
sudo systemctl enable --now postgresql
sudo -iu postgres createuser --pwprompt nexus
sudo -iu postgres createdb --owner=nexus nexus
```

3. Из папки проекта:

```fish
cp .env.example .env
```

Откройте `.env` в VS Code и задайте `DATABASE_URL` с вашим локальным пользователем/паролем PostgreSQL. Укажите собственное случайное значение `APP_SECRET` (например, сгенерировав его командой `openssl rand -base64 48`). Не копируйте `.env` в Git и не делитесь им.

4. Установите зависимости и сгенерируйте Prisma Client:

```fish
npm install
npm run db:generate
npm run db:migrate
npm run dev
```

Откройте `http://127.0.0.1:3000`. `npm run start` запускает сервер без режима наблюдения.

`npm run db:migrate` применяет уже зафиксированные миграции. `npm run db:dev` — удобная команда разработки Prisma, она может предложить создать новую миграцию, если схема менялась.

### Вариант B — PostgreSQL через Docker Compose

Нужны Docker и Docker Compose plugin. В `.env` задайте сильные `APP_SECRET` и `POSTGRES_PASSWORD`; затем выполните:

```fish
cp .env.example .env
# Измените APP_SECRET и POSTGRES_PASSWORD в .env
docker compose up --build
```

Приложение станет доступно на `http://127.0.0.1:3000`. База и загруженные файлы хранятся в Docker volumes. Остановка: `docker compose down`; данные остаются. Чтобы удалить данные базы, нужно отдельно удалить volume `nexus_pgdata` — не выполняйте это, если хотите сохранить переписки.

Для работы через Docker Compose приложение мигрирует базу при запуске. Не публикуйте этот dev-compose напрямую в интернет без production hardening.

## Аккаунт и восстановление

Регистрация выполняется без электронной почты: username, отображаемое имя, пароль и отдельный секрет восстановления. Секрет восстановления хранится в виде Argon2-хеша и не показывается повторно. Если потерять и пароль, и секрет восстановления, стандартного способа вернуть аккаунт нет.

Сессии хранятся на сервере; браузер получает только случайный токен в `HttpOnly` cookie. Сырые значения токенов не сохраняются в таблице сессий. Username нормализуется к нижнему регистру, а повторное изменение разрешается после семидневного периода. Удаление аккаунта откладывается на 30 дней; серверная периодическая очистка удаляет истёкшие записи. Владелец может отменить удаление через текущую сессию.

## Что реализовано в этом MVP

- Регистрация, вход, выход, сброс пароля через recovery secret, server-side sessions, завершение отдельных и остальных сессий.
- Уникальный нормализованный username; редактирование имени, username и краткого описания; серверное ограничение смены username раз в 7 дней.
- Личные диалоги, группы и каналы; добавление участников и одноразовые приглашения с ограниченным сроком; выход/удаление участников с базовыми проверками ролей.
- Сохранение и загрузка истории сообщений из PostgreSQL, пагинация истории по курсору времени, Socket.IO-сообщения, индикатор набора текста, read/delivery receipts в базе и интерфейсе, ответы, редактирование, удаление у себя/у всех, закрепление, реакции и архивирование.
- Поиск людей только по username; контакты отдельно от чатов; блокировки проверяются на сервере и в логике отправки/звонков/присутствия.
- Загрузка ограниченного набора типов файлов в непубличный каталог; ограничения размера и формата, случайные имена хранения и проверка членства при скачивании.
- Голосовые сообщения через MediaRecorder, когда браузер предоставляет микрофон; звонки один на один через WebRTC и Socket.IO signaling; настройки STUN/TURN через `.env`.
- Базовые RU/EN переводы, адаптивный интерфейс, тёмная дизайн-система, состояния пустой переписки, списков, ошибок и переподключения.

## Ограничения и известные недоработки

Это **MVP, а не полностью реализованная спецификация из master prompt**.

- В этой сборочной среде не было возможности скачать зависимости из npm, создать npm lock-файл, сгенерировать Prisma Client, применить миграцию к настоящей базе или прогнать end-to-end тесты. Прямые зависимости зафиксированы точными версиями в `package.json`, но транзитивное дерево ещё не закреплено lock-файлом.
- Загрузка аватаров и смена аватара пока не реализованы; поле и безопасный API-путь зарезервированы.
- Нет сквозного шифрования E2EE. Сервер и база способны видеть содержимое сообщений; передача по HTTPS в production должна быть настроена отдельно.
- Нет полноценной пересылки сообщений, сохранения отдельных чужих сообщений в «Сохранённое», сжатия изображений/параметра «оригинал», уведомлений браузера, пользовательского поиска по всей серверной истории и всех настроек приватности.
- Группы/каналы имеют базовое создание, участников и роли, но нет полного UI управления каждой ролью, каталогов каналов, расширенной системы подписок и всех потоков администрирования.
- WebRTC звонки — один на один; работоспособность между разными NAT/сетями зависит от TURN. Звонки в группе не реализованы. Локальный HTTP работает в localhost, но для доступа с телефона по LAN или публичного размещения используйте HTTPS.
- Текущая UX-проверка в реальном браузере, тестирование на физическом телефоне и внешний аудит безопасности не проводились.

## Проверка

Unit-тесты, не требующие сети или PostgreSQL:

```fish
npm test
```

Проверка доступности PostgreSQL после старта сервера:

```fish
curl http://127.0.0.1:3000/api/health
```

Для ручной проверки в браузере: создайте два отдельных аккаунта в разных браузерах/профилях; создайте личный чат по username; отправьте сообщения в обе стороны; обновите страницу и убедитесь, что история сохранилась; проверьте блокировку, загрузку/скачивание файла только участником чата, сессии, архив, RU/EN и узкую ширину окна. Для звонков необходимы разрешения браузера на микрофон/камеру.

Перед запуском интеграционных сценариев создайте **отдельную тестовую базу данных** и задайте её адрес через `DATABASE_URL`; никогда не указывайте рабочую базу пользователя. Интеграционный сценарий запускается командой `npm run test:integration`; он проверяет регистрацию, профиль, создание личного чата, получение Socket.IO-сообщения, историю и блокировку. Остальные сценарии из полного ТЗ пока не покрыты автоматическими интеграционными тестами.

## Безопасность и эксплуатация

- Production должен использовать HTTPS, `NODE_ENV=production`, сильный `APP_SECRET`, `Secure` cookies, ограниченный доступ к PostgreSQL, резервные копии и мониторинг диска/каталога файлов.
- Вход, регистрация и восстановление защищены ограничением частоты запросов; есть общий API rate limit, проверка Origin для изменяющих запросов, безопасные заголовки, Argon2id и минимальные лимиты текста/файла.
- Загруженные файлы не отдаются из статического каталога; endpoint скачивания проверяет авторизацию и членство в чате. Тип определяется по содержимому, а не только по имени файла.
- Не добавляйте секреты, реальные `.env`, пароли или пользовательские файлы в архив/Git. Не включайте логи тела запроса или содержимое переписок в production-логи.
- Конфигурация использует внешний TURN только при одновременном задании URL, username и credential. STUN по умолчанию не гарантирует соединение во всех сетях.

## Структура

```text
client/              адаптивный интерфейс и RU/EN словари
server/src/routes/   REST-маршруты
server/src/services/ логика личных чатов, сообщений и присутствия
server/src/sockets/  Socket.IO-события и сигнализация звонков
server/src/middleware/ сессии, проверка Origin и прав
server/prisma/       схема PostgreSQL и первоначальная миграция
tests/               unit-тесты чистых helper-функций
```
